# 技术方案：pywebview 桌面应用架构

## 1. 核心思路

项目采用“前端造壳，后端铸魂”的架构：

- 前端使用 HTML/CSS/JavaScript 绘制现代化桌面 UI。
- `pywebview` 使用系统 WebView 创建独立应用窗口。
- Python 后端负责摄像头、OpenCV、录像、文件、SQLite 和系统播放器调用。
- 桌面层负责应用图标、系统托盘、关闭行为和单实例唤起。
- 配置、数据和日志默认落到系统用户目录，开发模式可通过 `--config` 继续指定便携配置。

这个方案避免传统 Tkinter 界面的粗糙感，也避免纯浏览器 Web UI 的临时感，同时比 Electron 更轻。

## 2. 架构分层

### 2.1 前端表现层

技术：

- HTML5
- CSS3
- 原生 JavaScript

MVP 阶段暂不引入 Vue、React、Vite 或 Node 构建链。原因是当前界面规模可控，手写高质量 CSS 能获得更小的复杂度和更稳定的离线运行体验。

职责：

- 主控制台布局。
- 状态卡片。
- 布防/撤防交互。
- 事件时间线。
- 设置面板。
- VS Code 式设置页：左侧分类导航、右侧设置分区，每个设置项包含标题、说明和控件。
- 实时预览上的 ROI 选择、运动分数和热区叠加。
- 播放按钮和错误提示。

设计方向：

- 深色工作台风格。
- 信息密度适中。
- 动效克制但明确。
- 不出现浏览器地址栏、端口、网页服务感。
- 主题通过 CSS 变量实现，避免为了调整视觉风格频繁改动结构代码。

### 2.2 桥接与外壳层

技术：

- `pywebview`
- Windows: Edge WebView2
- macOS: WebKit
- Linux: GTK/WebKitGTK

职责：

- 创建独立桌面窗口。
- 加载本地前端资源。
- 暴露 Python 方法给 JavaScript。
- 将 UI 操作传递给后端。
- 将后端事件通知给 UI。
- 调用系统默认播放器打开录像。
- 管理系统托盘菜单、窗口隐藏/恢复和二次启动唤起。

注意：

- JS 暴露 API 不能直接操作后台线程内部状态。
- 后台状态更新应经过线程安全队列或受控服务层。
- 实时预览复用后台引擎最近帧缓存。预览开关关闭、离开总览页或窗口不可见时，后端不维护预览帧，前端不渲染。

### 2.3 核心后端层

技术：

- Python 3.10+
- OpenCV
- SQLite
- threading / queue
- pathlib / logging

职责：

- 摄像头采集。
- 低帧率运动检测。
- ROI 裁剪、运动分数统计和热区框提取。
- 预录制环形缓冲。
- 事件录像写入。
- 缩略图生成。
- SQLite 事件存储。
- 配置管理、系统目录解析和旧配置迁移。
- 日志与异常恢复。

说明：

- `core/` 只关心监控和录像。
- `bridge/` 只关心 UI 与 Python 通讯。
- `storage/` 只关心数据库和事件记录。
- `ui/` 是本地静态前端资源。

## 4. 数据流

1. 用户点击“布防”。
2. JavaScript 调用 pywebview 暴露的 Python API。
3. Python 桥接层通知后端引擎进入布防态。
4. 后台线程读取摄像头并低帧率检测运动。
5. 后端按配置裁剪 ROI，计算运动分数，并输出热区框给总览页。
6. 触发后，后端合成预录制片段和触发后片段。
7. 后端保存 MP4、JPG 和 SQLite 事件记录。
8. 桥接层通知前端刷新状态和时间线。
9. 用户点击播放。
10. Python 调用系统默认播放器打开本地录像。

## 5. 第一版技术决策

- UI 使用 pywebview 桌面窗口，而不是浏览器控制台。
- 前端第一版不用 Vue，保留后续升级空间。
- 事件索引用 SQLite，不用 JSONL 作为主存储。
- Webhook 告警暂缓到 v1.1。
- 预录制默认开启，但可配置关闭。
- 总览页支持实时预览，使用按需拉取的 JPEG 帧，帧率上限跟随采集帧率。
- 检测增强先采用轻量 OpenCV 路线：ROI 限定区域、运动分数和热区叠加，不引入重模型。
- 桌面体验默认开启关闭到托盘、最小化到托盘和单实例运行，避免误关窗口中断监控或重复占用摄像头。
- 新安装默认使用 `platformdirs` 提供的用户配置、数据和日志目录；旧项目配置首次迁移时会保留已有事件存储路径。
- Windows 开机自启使用当前用户 `Run` 注册表项，默认关闭，由用户主动启用。

## 6. 主要风险

- Windows 环境可能缺 WebView2 Runtime。
- 摄像头可能被其他软件占用。
- OpenCV 视频编码器在不同系统上支持程度不同。
- pywebview 的 JS/Python 桥接要注意线程安全。
- 无边框窗口需要自己实现拖拽、关闭、最小化等窗口控制。

## 7. 风险应对

- 启动时检查 WebView 和摄像头可用性。
- 录像编码优先使用常见兼容格式，失败时给出清晰错误。
- UI 与后端通过服务层交互，避免跨线程直接改状态。
- 第一版可先使用有边框窗口，视觉成熟后再切换无边框窗口。
